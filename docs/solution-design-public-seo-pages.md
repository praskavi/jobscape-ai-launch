# Solution Design: Public SEO Pages

## Jira

- Ticket: KAN-43
- Epic: KAN-25 - Implement Core Supabase Database Architecture for User, Storage, Billing, and AI Domains

## Problem / Goal

JobScrape has protected product routes for ATS scoring, AI job matching, resume scoring, and cover letter generation. These routes are not suitable SEO targets because they require authenticated user data.

The goal is to add public SEO landing pages and crawler metadata that explain the product capabilities, target high-intent search terms, and route users toward signup while keeping the actual app tools protected.

## Scope

- Add public SEO pages for:
  - `/ats-resume-checker`
  - `/ai-job-matching`
  - `/resume-match-score`
  - `/cover-letter-generator`
- Add reusable SEO feature-page layout.
- Add page-level metadata and canonical URLs.
- Add structured data for public feature pages.
- Add technical SEO foundation for:
  - `robots.txt`
  - `sitemap.xml`
  - site-wide metadata
  - landing-page structured data
- Fix footer placeholder links.
- Keep protected app routes out of the SEO sitemap.

## Design

Protected routes remain the product experience:

- `/atschecker`
- `/aijobmatch`
- `/dashboard`
- `/documents`
- `/subscription`
- `/settings`

Public SEO pages explain the value proposition and call users to create an account. They do not expose private user data, resume content, subscription state, or authenticated workflows.

Each SEO page uses:

- Unique title and description.
- Canonical URL.
- Search-intent-focused `h1`.
- Benefits section.
- Three-step workflow section.
- FAQ section.
- `WebPage` and `FAQPage` structured data.
- CTA to `/register` and secondary navigation to pricing where useful.

The landing page includes:

- Site-wide SEO metadata.
- OpenGraph and Twitter metadata.
- `SoftwareApplication`, `FAQPage`, and `Organization` structured data.

The sitemap includes only public pages. Protected routes are intentionally excluded or blocked by `robots.txt` where appropriate.

## User Stories

### Discover ATS Resume Checker

- Jira: KAN-43
- Who: As a job seeker searching for an ATS resume checker.
- What: I want to find a public page explaining how JobScrape checks my resume against a job description.
- Why: So that I can understand the value before creating an account.

### Discover AI Job Matching

- Jira: KAN-43
- Who: As a job seeker searching for AI job matching.
- What: I want to learn how JobScrape ranks jobs against my resume profile.
- Why: So that I can decide whether the tool can help me focus on better-fit roles.

### Discover Resume Match Score

- Jira: KAN-43
- Who: As a job seeker comparing a resume to a role.
- What: I want to understand how a resume match score helps prioritize applications.
- Why: So that I can spend time on roles where my resume has stronger alignment.

### Discover Cover Letter Generator

- Jira: KAN-43
- Who: As a job seeker writing many applications.
- What: I want to learn how an AI cover letter generator can create a role-specific draft.
- Why: So that I can save time while still reviewing and personalizing the final letter.

### Preserve Protected Product Routes

- Jira: KAN-43
- Who: As the JobScrape system.
- What: I want public SEO pages to point to signup while the actual tools remain protected.
- Why: So that private resume data and app workflows are not exposed to crawlers.

## Acceptance Criteria

- Public SEO pages exist for ATS resume checker, AI job matching, resume match score, and AI cover letter generator.
- Public SEO pages have unique metadata and canonical URLs.
- Public SEO pages use structured data.
- Public SEO pages CTA users to signup or pricing.
- `robots.txt` and `sitemap.xml` are generated by Next.js.
- Sitemap includes public SEO pages.
- Protected app/dashboard routes are not SEO targets.
- Footer links do not use placeholder `#` URLs.
- `npm.cmd run lint` passes.
- `npm.cmd run build` passes.
